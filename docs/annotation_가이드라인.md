## 1. 무엇을 판정하는가

목표 문장 안에서 **지정된 서술어의 생략된 주어가 누구인지**를 판정한다.

- 생략 위치를 찾는 과제가 아니다. 대상 서술어는 미리 표시되어 있다.
- 판정 단위는 **문항 1개 = 목표 문장 1개의 대상 서술어 1개**다.
- 답은 **대화 안의 특정 한 사람(인물 ID)** 이다. 역할(화자/청자/제3자)은 인물을 정한 뒤 계산한다.

### 판정 원칙

1. **원 주석을 보지 않는다.** 말뭉치에 있는 복원 형태(`내가`, `화자가` 등)와 선행어 연결은 판정 화면에 나오지 않는다. 원 주석에서 계산한 플래그(`perspective_conflict`, `hint_category` 등, 구현가이드 2.2–2.3절)도 판정 화면에 넣지 않는다. 판정이 끝나기 전에 원본 JSON이나 `gold_hints.jsonl`, `candidates.jsonl`을 열어 확인하지 않는다.
2. **목표 문장 끝까지만 본다.** 목표 문장 뒤의 대화는 보지 않는다. 목표 문장 안에서 서술어 뒤에 오는 표현은 볼 수 있다.
3. **확신할 수 없으면 정답을 만들지 않는다.** 애매하면 `multiple_plausible`, `insufficient`, `uncertain` 중 하나로 기록한다. 이것도 유효한 판정이다.
4. **혼자 판정한다.** 같은 문항을 맡은 다른 판정자와 조정 전까지 결과를 공유하지 않는다.
5. **종결어미·경어·화행도 정당한 근거다.** `-ㄹ게`, `-ㄹ래?`, 높임 표현 등으로 인물을 알 수 있으면 그것을 근거로 기록한다. 지름길이라고 배제하지 않는다.

## 2. 판정 화면 구성

### Full 조건

| 표시 내용 | 설명 |
|---|---|
| 대화 정보 | 참여자 2명을 `A`, `B`로 표시 (문서의 speaker ID와 대응표는 자료 담당이 관리) |
| 본문 | 대화 시작부터 **목표 문장 끝까지**, 문장마다 발화자 `A:`/`B:` 표시 |
| 목표 표시 | 목표 문장과 대상 서술어를 강조 |
| 인물표 | 대화의 인물 목록 (3절) |

### Local 조건

| 표시 내용 | 설명 |
|---|---|
| 본문 | **목표 문장 하나만**, 발화자 표시 포함 |
| 목표 표시 | Full과 같은 대상 서술어 강조 |
| 인물표 | Full과 같은 인물 목록 |

Local에도 인물표가 주어지므로, Local 판정은 "후보 목록이 주어진 상태에서 이 문장만으로 알 수 있는가"를 묻는 것이다 (설계안 5.4절).

## 3. 인물표와 인물 ID

인물표는 대화(conversation) 단위로 한 번 만들고, 그 대화의 모든 문항에서 같은 ID를 쓴다.

| ID | 대상 | 비고 |
|---|---|---|
| `P_A` | 참여자 A | 발화자 라벨 기준 |
| `P_B` | 참여자 B | 발화자 라벨 기준 |
| `T1`, `T2`, … | 대화에 참여하지 않는 제3자 | 처음 등장한 순서대로 번호. 이름·호칭·짧은 설명을 적는다 |

### 같은 인물로 묶는 규칙

- 같은 사람을 가리키는 이름, 지칭 표현(`우리 엄마`, `그 친구`), 대명사는 하나의 ID로 묶는다.
- **`나/저`는 그 말을 한 문장의 발화자**, **`너/네/니`는 그 문장의 상대 참여자**에 연결한다. 목표 문장의 발화자 기준이 아니다.
  - 예: A가 말한 문장의 `나` → `P_A`. 이후 B의 문장에서 그 사람을 가리켜도 인물은 `P_A`다.
- 호칭어(`형`, `언니`, `오빠`, `누나`, `자기`)는 **그 호칭이 실제로 가리키는 사람**에 연결한다. 상대를 부르는 말이면 대개 상대 참여자지만, 제3자 가족을 가리킬 수도 있으므로 문맥으로 판단한다.
  - `자기`는 연인·부부 대화에서 2인칭(상대)으로 쓰일 수 있고, 재귀 표현(그 사람 자신)일 수도 있다.
- 말뭉치에서 인명은 `name1`, `name2`…로 익명화되어 있다. 이것을 **이름으로 보고** 같은 번호는 같은 사람으로 묶는다. 조사가 붙은 형태(`name1이`, `name1이는`)도 같다. 단, 번호는 문서 안에서만 의미가 있으므로 다른 대화의 `name1`과 같은 사람으로 보지 않는다.
- 동일 인물인지 근거가 부족하면 새 ID를 만들지 말고 메모에 `동일인 불확실`을 적는다.
- 제3자 목록이 판정 중 부족하면 `T_NEW`로 적고 설명을 남긴다. 조정 단계에서 ID를 확정한다.

> 제3자 후보는 자료 담당이 익명화 이름(`name*`)과 관계 명사(`선생님`, `엄마`, `남편` 등, 구현가이드 3.2절)로 미리 뽑는다. 관계 명사는 참여자 본인을 부르는 말일 수도 있으므로(예: 상대를 `선생님`이라 부름) 후보 목록은 초안일 뿐이고, 어떤 인물로 연결할지는 판정자가 정하고 조정 때 확정한다. 작성 절차는 8절 미결 사항 1번.

## 4. 판정 절차

문항 하나를 아래 순서로 판정한다. 각 단계의 기록 필드는 7절 양식과 같다.

### 1단계: 대상 적합성 확인

아래에 해당하면 **제외**하고 `exclusion_reason` 코드를 적은 뒤 다음 문항으로 넘어간다. 여러 개면 가장 앞의 것 하나를 적고 나머지는 메모에 쓴다.

| 코드 | 의미 |
|---|---|
| `EX_OVERT` | 대상 서술어의 주어가 실제로 문장에 있다 (생략이 아님) |
| `EX_NOT_SUBJECT` | 생략된 것이 주어가 아니다 |
| `EX_NONHUMAN` | 주어가 사람이 아니다 (사물, 동물, 사건, 기관) |
| `EX_PLURAL` | 복수 또는 집합이다 (`우리`, `저희`, A와 B 둘 다, 가족 전체 등) |
| `EX_GENERIC` | 일반·불특정 지시다 (사람들 일반, `누군가`) |
| `EX_COMPLEX_CLAUSE` | 복잡한 인용절·내포절, 통제구문이라 대상 절의 주어 판단이 불안정하다 |
| `EX_PREDICATE` | 대상 서술어 표시가 맞지 않거나 어떤 서술어인지 불분명하다 |
| `EX_TEXT` | 정제문에 문제가 있어 해석할 수 없다 (잘림, 오탈자, 비문) |
| `EX_SPEAKER_LABEL` | 발화자 라벨이 본문과 명백히 맞지 않는다 |

- 주어가 사람인지, 단수인지 자체가 애매하면 제외하지 말고 2단계로 가서 `uncertain`으로 판정한다.
- 목표 뒤 문맥이 있어야 알 수 있을 것 같다는 이유로는 제외하지 않는다. 2단계에서 `insufficient`로 판정한다.

### 2단계: Full 판정 (인물과 충분성)

목표 문장 끝까지의 대화를 읽고 다음을 기록한다.

**`full_resolvability`**

| 값 | 기준 |
|---|---|
| `unique` | 인물표 중 **한 사람**으로 정해지고, 다른 판정자도 같은 사람을 고를 것이라고 확신한다 |
| `multiple_plausible` | 두 명 이상이 그럴듯하고 하나로 좁힐 근거가 부족하다 |
| `insufficient` | 주어진 문맥에 인물을 정할 정보가 없다 |
| `uncertain` | 판단이 계속 흔들리거나, 단수 인간 여부 자체가 불분명하다 |

- `unique`일 때만 `referent_entity_id`를 적는다. 그 외에는 비워 두고, 그럴듯한 후보가 있으면 메모에 적는다.
- 확신 판단 기준: "근거 표현을 짚어 설명할 수 있는가". 느낌만으로는 `unique`가 아니다.

**`support_spans`** (`unique`일 때 필수)

정답을 정한 근거를 문장 번호(판정 화면 기준)와 표현으로 적는다. 근거 유형을 함께 표시한다.

| 근거 유형 | 예 |
|---|---|
| `mention` | 앞 문맥의 이름, 지칭 표현, 대명사 |
| `ending` | 종결어미·양태 (`-ㄹ게`, `-ㄹ래?`, `-더라`, 의문문 등) |
| `honorific` | 높임 표현 |
| `speech_act` | 질문-대답, 제안-수락 같은 대화 흐름 |
| `world` | 상식·상황 지식 |

**`reference_mode`**

| 값 | 기준 |
|---|---|
| `textual_anaphoric` | 근거가 앞 문맥의 명시적 언급이다 |
| `deictic` | 텍스트 언급 없이 대화 참여자(화자·청자)를 가리킨다. 근거가 어미·경어·화행이다 |
| `mixed` | 두 종류의 근거가 함께 필요하다 |
| `uncertain` | 근거 유형을 정하기 어렵다 |

- `future_dependent`는 판정자가 쓰지 않는다. 원 주석의 선행어가 목표 뒤에만 있는 문항(`has_future_antecedent`)은 판정 전에 필터에서 빠진다 (구현가이드 3.2절). 그래도 남은 문항에서 원 주석 대조(6절) 때 뒤 문맥 의존이 드러나면 조정자가 붙인다.

**`last_mention_sentence`**: 목표 이전에 정답 인물이 텍스트로 마지막 언급된 문장 번호. 텍스트 언급이 없으면 `NA`. 거리는 나중에 코드로 계산한다.

### 3단계: 역할 계산

`unique`이면 정답 인물을 **목표 문장의 발화자 기준**으로 바꾼다.

| 정답 인물 | `referent_role` |
|---|---|
| 목표 문장의 발화자 | `speaker` |
| 목표 문장의 상대 참여자 | `addressee` |
| 제3자 (`T*`) | `third_party` |

2인 대화이므로 목표 문장의 청자는 상대 참여자로 본다. 역할이 같아도 다른 제3자를 고르면 다른 답이다.

### 4단계: anchor와 전환 판정

Full이 `unique`인 문항만 한다. 정의는 설계안 6절을 따른다.

**anchor 찾기**

1. 목표 문장 바로 앞 문장부터 거꾸로 올라가며 **주절**을 하나씩 본다. v0에서는 목표 문장 안의 앞선 절은 보지 않는다 (8절 미결 사항 4번).
2. 인용절·내포절은 건너뛴다.
3. 주절의 주어가 사람이 아니거나 복수면 건너뛴다.
4. 주절의 주어가 단수 인간이고 **인물을 정할 수 있으면** 그 절이 anchor다.
5. 주절의 주어가 단수 인간인데 **인물을 정할 수 없으면 멈추고** 전환 값을 모두 `NA`로 둔다. 더 위로 올라가 편한 anchor를 찾지 않는다.
6. 대화 시작까지 anchor가 없으면 `NA`.

anchor의 주어는 명시된 주어일 수도, 생략된 주어일 수도 있다. 생략된 경우에도 판정자가 인물을 확신할 수 있어야 한다.

**기록**

| 필드 | 값 |
|---|---|
| `anchor_sentence` | anchor 절이 있는 문장 번호 |
| `anchor_entity_id` | anchor 주어의 인물 ID |
| `anchor_speaker` | anchor 문장의 발화자 (`A`/`B`) |
| `entity_switch` | anchor 주어와 목표 주어가 **다른 인물**인가 |
| `speaker_switch` | anchor 문장과 목표 문장의 **발화자가 다른가** |
| `role_switch` | 각 문장의 발화자 기준으로 계산한 주어 역할이 다른가 |
| `target_role_remap` | 목표 인물을 anchor 발화자 기준과 목표 발화자 기준에 놓았을 때 역할이 달라지는가 |

- 같은 사람이 speaker에서 addressee로 바뀌는 것은 `entity_switch = false`다.
- 다른 제3자로 바뀌면 역할이 같아도 `entity_switch = true`다.

### 5단계: 메모

판정이 쉽지 않았던 이유, 다른 후보, 가이드라인으로 해결되지 않은 점을 적는다. 이 메모가 v1 수정의 재료가 된다.

## 5. Local 판정

Local 판정은 **그 문항의 Full 판정과 조정 결과를 보지 않은 사람**이 Full보다 먼저 한다 (설계안 5.3절 6번, 역할분담 3주차 배정표).

1. 목표 문장 하나와 인물표만 본다.
2. 1단계 제외 판정은 하지 않는다 (Full 쪽에서 한다).
3. `local_resolvability`를 2단계와 같은 기준으로 적는다.
4. `unique`이면 인물 ID와 근거를 적는다.
5. 끝난 뒤에 같은 문항의 Full 조정을 맡는다.

Full이 `unique`가 아닌 문항은 나중에 `local_resolvability = not_assessed`로 처리할 수 있다. Local을 먼저 하므로 판정 시점에는 알 수 없으니 일단 모두 판정한다.

문맥 필요성 분류는 조정 후 자동으로 계산한다 (설계안 5.4절).

| Full | Local | 분류 |
|---|---|---|
| unique | unique, 같은 인물 | locally recoverable |
| unique | multiple_plausible 또는 insufficient | discourse-dependent |
| unique | unique, 다른 인물 / uncertain | conflict, 재검토 |

## 6. 조정과 원 주석 대조

### 조정 (adjudication)

1. 두 판정자의 Full 결과를 비교한다.
2. 아래 중 하나라도 다르면 조정 대상이다: 제외 여부, `full_resolvability`, `referent_entity_id`, `reference_mode`, anchor 인물, 전환 값.
3. 조정자는 두 판정과 근거를 보고 최종 값을 정하고 **이유를 적는다.** 최초 판정은 지우지 않는다.
4. 조정자도 확신할 수 없으면 `uncertain`으로 둔다. 다수결로 정하지 않는다.
5. 가이드라인으로 해결되지 않는 유형이 나오면 메모에 `GUIDE`를 붙여 다음 회의 안건으로 올린다.

일치도는 조정 전 두 판정으로 계산하고 **gold 제작 품질**로만 보고한다. 조정 후 결과를 인간 상한이라고 부르지 않는다.

### 원 주석 대조 (조정 후에만)

조정이 끝난 문항에 대해 조정자가 원 주석을 열어 비교하고 `source_comparison`을 적는다.

| 값 | 의미 |
|---|---|
| `match` | 원 주석과 같은 인물 |
| `person_copy` | 원 주석의 복원 형태가 선행어 인칭을 복사한 것이라(2025 지침 2.2.3.2) 형태는 다르지만 인물은 같다 |
| `antecedent_error` | 원 주석의 선행어 연결이 다른 사람을 가리킨다 |
| `future_context` | 원 주석의 근거가 목표 뒤에만 있다 → `reference_mode = future_dependent` |
| `text_issue` | 정제문·발화자 라벨 문제 |
| `other` | 그 밖의 차이, 메모 필수 |

- **정답은 언제나 우리 독립 판정 결과다.** 원 주석과 다르다고 우리 판정을 고치지 않는다. 대조 결과는 기록만 한다.
- 상대 화자의 `나/너`에 연결된 347건(`perspective_conflict = true`)도 판정 단계에서는 다른 문항과 똑같이 독립 판정한다. 조정자는 조정이 끝난 뒤 이 플래그를 보고 원 주석의 인칭 복사(`person_copy`)인지 선행어 오연결(`antecedent_error`)인지 구분해 기록한다. 원 주석의 형태나 연결을 자동으로 변환하지 않는다.
- 원 주석을 보고 판정 기준 자체를 바꿔야 한다고 생각되면 해당 subset 전체를 같은 기준으로 다시 검토한다. 모델이 틀린 문항만 골라 정답을 바꾸지 않는다.

## 7. 판정 기록 양식

판정 파일은 `annotations/development/`, `annotations/heldout/`에 둔다 (Git 제외). 스프레드시트로 작업하고 조정 후 JSONL로 변환한다. 필드 이름은 `annotation.schema.json`을 따른다.

### 판정자별 시트 (한 행 = 한 문항의 한 판정)

| 열 | 값 | 언제 |
|---|---|---|
| `item_id` | 자료 담당이 부여 | 항상 |
| `annotator` | 판정자 이름 | 항상 |
| `condition` | `full` / `local` | 항상 |
| `exclusion_reason` | 1단계 코드 또는 빈칸 | Full |
| `resolvability` | unique / multiple_plausible / insufficient / uncertain | 항상 |
| `referent_entity_id` | `P_A`, `P_B`, `T1` … | unique일 때 |
| `referent_role` | speaker / addressee / third_party | unique일 때 |
| `reference_mode` | textual_anaphoric / deictic / mixed / uncertain | Full, unique일 때 |
| `support_spans` | `문장번호:표현:근거유형` 여러 개는 `;`로 구분 | unique일 때 |
| `participant_anchor` | 근거가 `나/너`일 때 그 표현이 나온 문장 번호와 발화자 | 해당 시 |
| `last_mention_sentence` | 문장 번호 또는 `NA` | Full, unique일 때 |
| `anchor_sentence` | 문장 번호 또는 `NA` | Full, unique일 때 |
| `anchor_entity_id` | 인물 ID 또는 `NA` | Full, unique일 때 |
| `anchor_speaker` | `A` / `B` / `NA` | Full, unique일 때 |
| `entity_switch` | true / false / NA | Full, unique일 때 |
| `speaker_switch` | true / false / NA | Full, unique일 때 |
| `role_switch` | true / false / NA | Full, unique일 때 |
| `target_role_remap` | true / false / NA | Full, unique일 때 |
| `memo` | 자유 기록, `GUIDE` 표시 가능 | 선택 |
| `minutes` | 걸린 시간(분) | 선택, 작업량 추정용 |

### 조정 시트 (한 행 = 한 문항)

| 열 | 값 |
|---|---|
| `item_id` | |
| `adjudicator` | 조정자 이름 |
| 최종 값 | 위 판정 필드와 같음 |
| `changed_fields` | 두 판정과 달라진 필드 목록 |
| `reason` | 조정 이유 |
| `source_comparison` | 6절 대조 값 |
| `local_resolvability` | Local 판정자의 값 |
| `context_need` | locally recoverable / discourse-dependent / conflict |

`source_comparison`, `context_need`, `minutes`는 현재 스키마에 없는 필드다. v1 동결 때 스키마에 추가할지 정한다.

## 8. 미결 사항 (pilot에서 정할 것)

| 번호 | 문제 | v0 처리 | 정할 사람 |
|---|---|---|---|
| 1 | 인물표를 누가, 언제 만드는가 | 자료 담당이 후보 초안(익명화 이름 + 관계 명사)을 만들고, 판정자가 `T_NEW`로 추가, 조정 때 확정 | 서진정 + 정택준 |
| 2 | turn 단위 | 문장 번호로 기록. speaker-run proxy 여부는 자료 담당 audit 결과에 따름 | 정택준 |
| 3 | 문장 ID에 한 단계가 더 있는 662개 | 판정 화면에서는 일반 문장과 같이 표시. 의미 확인 후 재검토 | 정택준 |
| 4 | 목표 문장 안의 앞선 절을 anchor로 볼지 | 보지 않음 | 전원 |
| 5 | 연결어미로 이어진 절(`-고`, `-는데`)의 주절 판단 | 문장의 마지막 서술어 절을 주절로 봄 | 전원 |
| 6 | `자기`, 호칭어의 인물 연결 | 문맥으로 판단, 메모 필수 | 전원 |
| 7 | 판정 화면에서 A/B 대신 성별·관계 정보를 보여줄지 | 보여주지 않음 (모델 입력과 맞춤) | 전원 + 임동건 |
| 8 | Full 입력이 아주 긴 문항 | 판정은 하되 모델 입력 한도를 넘으면 평가에서 제외 | 임동건 |
| 9 | 판정 화면 제작 방식 (스프레드시트 / 간단한 HTML) | 스프레드시트 | 정택준 |

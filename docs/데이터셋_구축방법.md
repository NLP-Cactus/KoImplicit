# KoImplicit 데이터셋 구축 방법 (v2.2, 2026-10-10)

- 상태: 구현 완료, Pilot v0 후보 20개 작성, **사람 검수 전**. 외부 모델 평가는 수행하지 않았다(mock provider로 파이프라인만 검증).
- 이 문서가 데이터 구축·평가 절차의 현행 기준이다. [최종설계안.md](../최종설계안.md) v2.0의 연구 질문·지표 정의는 유지하되, 말뭉치 확보·audit·자연 자료 split 절차는 폐기한다.
- v2.2 변경(교차검증 반영): Local 판정 절차와 문맥 필요성 분류 추가, anchor·청자 판정 규칙 명시, 중립 후보 ID, 실제 payload 누수 검사, pair 단일성 기준 강화, 재실행·검수 상태 검증 규칙.

## 1. 연구 질문과 변수

| RQ | 변수 | 데이터에서의 구현 |
|---|---|---|
| RQ1 정확도·문맥 필요성 | `gold_referent_role` ∈ {speaker, addressee, third_party}, `context_need` | 역할은 목표 발화의 화자 기준. `context_need`는 사람의 Full 판정과 Local(목표 발화만) 판정을 비교해 locally_recoverable / discourse_dependent / conflict로 분류한다(6절) |
| RQ2 전환 | `speaker_changed`, `referent_changed`, `referent_role_changed` | anchor(2절 규칙)와 비교. anchor가 없으면 `None` |
| RQ3 표면 단서 | `distractor_present`, `turn_distance`, `linguistic_cues`, 조건 `target_only_mcq` | 최근 언급 개체, 거리, 어미·호격·높임 단서를 변형으로 조작하고 target-only 조건·휴리스틱 기준선과 비교 |

`turn_distance`는 목표 발화와 정답의 마지막 **명시 언급** 사이 턴 수다. 텍스트 언급 없이 화자·청자를 가리키는 deictic 사례는 `None`이다. `distractor_present`는 정답의 마지막 언급 이후에 다른 인물이 언급되었는가(작성자가 `distractor_id`를 지정하면 그 인물 기준, 아니면 가장 최근 언급 개체 기준)다. gold가 없으면 `None`이고 distractor 통계의 분모에 넣지 않는다.

RQ1의 문맥 이득(`context_benefit`)은 같은 항목의 full − target_only 정답 차이다. 이 값은 `context_need` 분류별로 나눠 보고하며, Local에서 사람도 답할 수 없는 항목의 낮은 target-only 정확도를 모델 결함으로 세지 않는다.

RQ2의 셀(`referent_changed × speaker_changed`)은 표본 수가 아니라 **독립 scenario 수**로 보고한다. 셀이 비거나 scenario가 2개 미만이면 그 비교는 제시하지 않는다(Pilot v0는 `speaker_changed=False`가 1개뿐이다).

## 2. 판정 규칙 (작성자·검수자 공통)

**역할**: 목표 발화 화자 = speaker, 목표 발화의 청자 = addressee, 그 외 = third_party. 2인 대화의 청자는 상대 참여자다.

**3인 대화의 청자**: 다음 중 하나로 확정한다. (a) 호격이나 2인칭 지시 표현, (b) 인접쌍(질문–답, 요청–정보 보유자)과 발화 내용이 함께 한 사람을 가리킴. 둘 이상 해석이 남으면 `addressee_id`를 비우고 참여자가 정답일 때는 gold도 비운다. N02-01은 (b)의 예이고 S03-novocative는 확정 불가의 예다. 검수자는 `addressee_id`를 독립적으로 판정하며 불일치는 조정 대상이다.

**anchor(이전 참조 대상)**: 목표 이전 발화를 거꾸로 보며, 각 발화의 마지막 절에서 **사람을 가리키는 주어**가 단수 인물로 확정되는 첫 발화. 여기서 주어는 문법 주어뿐 아니라 경험자·대주어(예: "나도 일요일이 좋아"의 경험자, "출퇴근은 편해졌겠네?"의 대주어)를 포함한다. 복수·비인간·불확정 주어 발화는 건너뛰되, 단수 인물인데 누구인지 확정할 수 없으면 멈추고 anchor를 `None`으로 둔다. 이 규칙은 설계안 6절의 "주절 주어" 정의를 경험자·대주어로 확장한 것이다. anchor는 **시나리오 설계 단계에서 작성자가 선언하는 실험 변수**이며 검수자가 판정하지 않는다(Pilot 검수에서 판정 부담이 커 뺐다). 그 타당성은 pair 검수(조작이 의도대로인가)와 작성 근거 기록으로 확인하고, 독립 검증이 없다는 점을 한계로 보고한다. 역할(speaker/addressee/third_party)도 검수 항목이 아니며 인물·화자·청자에서 코드가 계산한다.

**정답 확정**: 작성자 라벨은 의도값이다. 검수자 2명이 독립적으로 같은 인물을 `unambiguous`로 고를 때만 gold가 된다. 단서(어미·호격·어휘)로 풀리는 것은 오류가 아니며 `linguistic_cues`로 기록해 분리 분석한다.

## 3. 데이터 제작 원칙

1. 국립국어원 무형 대용어 복원 말뭉치 2024/2025의 문장·대화를 쓰지 않는다. 인명·장소만 바꾼 변형도 만들지 않는다. 말뭉치를 외부 API에 보내지 않는다.
2. 공개 문헌에서는 언어 현상(주어 생략, 전문 어미 `-대`, 호격, 높임, 인접쌍)과 실험 방법론만 참고한다.
3. 모든 대화는 시나리오 명세(`datasets/scenarios/*.jsonl`)를 먼저 쓰고 그 조건에 맞춰 새로 작성한다.
4. 모든 표본에 `creation_method`, `generation_metadata`(모델·provider·프롬프트 버전·날짜·작성자·수정자), `annotation_status`, `validation_metadata`를 기록한다.
5. **Controlled**는 독립변수를 통제한 변형 family다. **Naturalistic**은 pair 없이 쓴 "시나리오로 유도한 비쌍 창작 대화"이며, 자연 발생 분포의 표본이 아니다. 실제 수집 자료라고 부르지 않고, 그 정확도를 자연 대화의 평균 성능으로 제시하지 않는다.

| `labels.jsonl` | `LabelRecord` | addressee_id, gold_referent_id, anchor_turn(1 이상, 목표 이전), anchor_referent_id, anchor_addressee_id, distractor_id, ambiguity_status, annotation_status, linguistic_cues, manipulated_variables, pair_claims, pair_expected_gold_change, expected_gold_change, author_rationale, validation_metadata |

언급 탐지는 모든 참여자의 표면형을 모아 긴 표현부터 겹침 없이 찾는다("형수님"이 "형"보다 먼저). 스키마 제약: 2~6턴, 발화 참여자 2~3명, 서술어는 목표 발화 안에서 정확히 한 번, 대화 텍스트에 entity_id 문자열 금지, `accepted`이면 gold와 `unambiguous` 필수, gold가 없으면 `unambiguous` 불가, 중복 sample_id 불가.

## 6. 검수 절차 (2명 독립 → 일치도 → pair → 조정)

1. **Full 시트** `annotate sheets --condition full`: 검수자별 CSV. `sample_id` 대신 불투명 `review_id`(대응표 `id_map.json`)를 쓰고 family·variant·작성자 라벨을 숨기며 순서를 섞는다. 항목: 자연스러움(1~5), referent_id, addressee_id(3인 대화만), context_sufficient, ambiguity, notes. 역할과 anchor는 묻지 않는다(2절).
2. **Local 시트** `annotate sheets --condition local`: 목표 발화와 후보만 보여 준다. Full 정답을 보지 않은 검수자가 먼저 판정하는 것이 원칙이며, 같은 사람이 둘 다 하면 순서·기억 영향을 한계로 기록한다.
3. `annotate agreement`: 조건별·필드별 percent agreement, Cohen's κ(단일 범주면 정의되지 않아 None), 결측 수. `determinable`(확정 가능 여부)은 ambiguous/uncertain 라벨 차이를 합친 값이라 Local 비교의 기준이 된다. 이 값은 gold 제작 품질이지 인간 상한이 아니다. referent_id κ는 표본마다 ID가 다른 인물을 가리키므로 해석에 주의한다.
4. `annotate pair-sheet`: 독립 판정이 끝난 뒤 두 버전을 나란히 보고 pair_valid, only_claimed_changed, gold_change_as_intended를 판정한다.
5. `annotate adjudicate`: Full 판정으로 결정한다. 전원 일치(정답·unambiguous) → accepted; 전원 모호 → rejected; 불일치 → `adjudication.csv`(decision, final_referent_id, final_ambiguity, final_addressee_id, reason). 청자는 전원 일치 값을 반영하고 불일치는 조정값 또는 작성자 값 유지 + `addressee_disputed` 기록. anchor는 작성자 값을 유지한다. 같은 검수자 중복 행·후보 밖 ID는 거부한다. 최초 판정은 전부 `validation_metadata.annotator_votes`에 보존하고 작성자 값이 바뀌면 `author_values_overridden`에 기록한다. Local 판정이 있으면 `context_need`를 분류해 저장한다.
6. 조정 라벨은 새 버전 폴더(`datasets/pilot_v1/`)에 `dialogues.jsonl`과 함께 동결한다. accepted만 `payload`에 들어간다. 모델 결과를 본 뒤 gold·후보·제외 기준을 바꾸지 않는다.

## 8. 평가 설정

- 조건: `full_mcq`, `target_only_mcq`(목표 발화만 + 후보), `full_qa`(후보 없음). MCQ는 프롬프트로 JSON 한 줄을 요청하고 파서가 검증한다(API 수준의 schema 강제는 쓰지 않는다). QA는 자유 서술을 `normalize.map_qa_answer`로 entity ID에 매핑하며, 거부 표현을 먼저 판정하고 청자 대명사는 2인 대화에서만 상대 참여자로 매핑한다. 출력 지시 방식은 MCQ 두 조건에서 같다.
- 프롬프트: `prompts/mcq_v1.json`, `qa_v1.json`. 후보는 중립 ID와 이름만 노출한다.
- 모델 설정: `configs/models.json`(provider, model_id, decoding, 단가, seed 지원 여부). 실행마다 `config.json`에 model_id·prompt 해시·items 해시·날짜·조건·검수 상태를 기록한다. OpenAI decoding 키는 그대로 전달되므로 `max_completion_tokens` 등 현행 파라미터 이름을 쓴다.
- 재시도: 네트워크·서버 오류·불완전 수신·비JSON 응답만 같은 payload로 최대 2회(Retry-After 반영). 형식 오류·오답을 보고 재질문하지 않는다.
- 구독 CLI provider(`claude_cli`, `codex_cli`)는 개발·pilot 점검용이다. Claude Code는 `--system-prompt`로 기본 프롬프트를 대체할 수 있지만 Codex는 에이전트 프롬프트가 항상 붙는다. 실행 기록에 `system_prompt_mode`, `cli_version`을 남기고, 논문 수치는 API provider로만 보고한다.
- 지표: overall accuracy, by referent type / shift / speaker change / distractor / distance / dataset / creation_method / context_need / linguistic_cue, distractor error rate(gold 있는 표본만), context benefit, pair consistency(방향별 harm·recovery, pair_valid가 확인된 pair만 공식 집계), role confusion matrix, candidate-slot confusion(중립 ID 슬롯 기준이며 인물 혼동이 아님), parse status 비율. QA 조건에는 후보 기반 chance level을 내지 않는다. CI는 scenario 단위 cluster bootstrap.
- 후보 위치: family 안에서는 순서를 고정하므로 정답 위치 분포를 보고하고, 본 실험에서는 결과를 보기 전에 정한 순서 교차 평가로 민감도를 확인한다.

## 9. 재현성

- seed 기본값 20261010. 중립 ID·후보 순서(payload), 검수 시트 ID·순서(annotate), 요청 순서(runner)에 쓰인다.
- 데이터셋 버전: 폴더 이름(`pilot_v0` → 조정 후 `pilot_v1`)과 레코드 `version`. 동결 후 변경은 새 버전으로.
- 프롬프트는 `prompts/`에 버전 파일로 두고 실행 기록에 sha256을 남긴다. 응답은 payload 해시로 캐시된다. API 키는 환경 변수로 설정한다(`.env` 자동 로딩 없음).

## 10. 알려진 편향과 위험

- **생성 모델 = 평가 모델 편향**: Pilot 작성자(Claude Fable 5.1)와 평가 후보(Claude 계열)가 같은 계열이다. `by_creation_method` 집계로 human_authored 표본과 비교하도록 설계했다. Pilot 작성·검수 일치도를 독립 인간 상한으로 해석하지 않는다.
- **작성자 라벨 오류 가능성**: 7절의 확인 표본 목록. 검수에서 확정한다.
- **단서 의존**: N03의 `친정`, N01의 높임 부재, S07의 `-대`, S03의 호격처럼 target-only로 이미 풀리는 표본이 있다. `context_need`와 `linguistic_cues`로 분리하고 높은 점수를 장거리 추적의 증거로 일반화하지 않는다.
- **역할·셀 불균형**: 제3자 11/20, `speaker_changed=False` 1/20. 확장 시 화자·청자와 화자 유지 표본을 늘린다.
- **compound 변형**: 5개 pair는 단일 변수 조작이 아니다. 단일 cue minimal pair라고 부르지 않는다.
- **3인 대화 청자**: 호격 없는 청자 판정(N02)은 담화 추론에 의존한다. 검수자 불일치가 크면 제외한다.
- **anchor 독립 검증 없음**: shift 변수(RQ2)는 작성자가 선언한 anchor에서 계산되며 검수자가 따로 판정하지 않는다. RQ2 결과는 설계 변수 기준의 연관으로만 보고한다.
- **규모**: 20개는 pilot이다. 셀별 표본이 작아 CI가 넓다. 600개 확장은 pilot 검수와 스키마 동결 뒤에 한다.

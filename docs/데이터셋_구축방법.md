# KoImplicit 데이터셋 구축 방법 (v2.1, 2026-10-10)

- 상태: 구현 완료, Pilot v0 후보 20개 작성, **사람 검수 전**. 외부 모델 평가는 수행하지 않았다.
- 이 문서가 데이터 구축·평가 절차의 현행 기준이다. [최종설계안.md](../최종설계안.md) v2.0의 연구 질문과 지표 정의는 유지하되, 말뭉치 확보·audit·자연 자료 split 절차는 폐기한다.

## 1. 연구 질문과 변수

| RQ | 변수 | 데이터에서의 구현 |
|---|---|---|
| RQ1 정확도 | `gold_referent_role` ∈ {speaker, addressee, third_party} | 목표 발화의 화자 기준으로 계산. 2인 대화는 상대가 청자, 3인 대화는 `addressee_id`를 명시해야 하며 못 하면 역할을 확정하지 않는다 |
| RQ2 전환 | `speaker_changed`, `referent_changed`, `referent_role_changed` | anchor(목표 이전 가장 가까운 단수 인간 주어 발화)와 비교. anchor가 없으면 `None` |
| RQ3 표면 단서 | `distractor_present`, `turn_distance`, `linguistic_cues`, 조건 `target_only_mcq` | 최근 언급 개체, 거리, 어미·호격·높임 단서를 변형으로 조작하고 target-only 조건과 비교 |

`turn_distance`는 목표 발화와 정답의 마지막 **명시 언급** 사이 턴 수다. 화자·청자를 텍스트 언급 없이 가리키는 deictic 사례는 `None`이다. `distractor_present`는 정답의 마지막 언급 이후에 다른 인물이 언급되었는가(작성자가 `distractor_id`를 지정하면 그 인물 기준, 아니면 가장 최근 언급 개체 기준)다.

## 2. 데이터 제작 원칙

1. 국립국어원 무형 대용어 복원 말뭉치 2024/2025의 문장·대화를 쓰지 않는다. 인명·장소만 바꾼 변형도 만들지 않는다. 말뭉치를 외부 API에 보내지 않는다.
2. 공개 문헌에서는 언어 현상(주어 생략, 전문 어미 `-대`, 호격, 높임, 인접쌍)과 실험 방법론만 참고한다.
3. 모든 대화는 시나리오 명세(`datasets/scenarios/*.jsonl`)를 먼저 쓰고, 그 조건에 맞춰 새로 작성한다.
4. 모든 표본에 `creation_method`, `generation_metadata`(모델·provider·프롬프트 버전·날짜·작성자·수정자), `annotation_status`, `validation_metadata`를 기록한다.
5. **Controlled**는 독립변수를 통제한 변형 family, **Naturalistic**은 통제 없이 자연스럽게 쓴 독립 대화다. Naturalistic은 실제 수집 자료가 아니며 그렇게 주장하지 않는다.

## 3. 스키마 (`src/koimplicit/schema.py`)

두 레코드를 물리적으로 분리한다.

| 파일 | 레코드 | 내용 |
|---|---|---|
| `dialogues.jsonl` | `DialogueRecord` | sample_id, dataset, scenario_id, template_id, family_id, pair_ids, variant, participants(entity_id·name·aliases·in_dialogue), dialogue(turn_index·speaker_id·text), speaker_id(목표 화자), target_turn, target_predicate(+span), omitted_argument, creation_method, generation_metadata |
| `labels.jsonl` | `LabelRecord` | addressee_id, gold_referent_id, anchor_turn, anchor_referent_id, distractor_id, ambiguity_status, annotation_status, linguistic_cues, manipulated_variables, pair_claims, expected_gold_change, author_rationale, validation_metadata |
| (계산) | `Derived` | gold_referent_role, anchor_referent_role, speaker_changed, referent_changed, referent_role_changed, turn_distance, distractor_present, most_recent_mentioned_id 등 |

스키마 제약: 2~6턴, 발화 참여자 2~3명, 서술어는 목표 발화 안에서 정확히 한 번, 대화 텍스트에 entity_id 문자열 금지, `accepted`이면 gold와 `ambiguity_status=unambiguous` 필수, gold가 없으면 `unambiguous` 불가.

## 4. 파이프라인

| 단계 | 모듈 / 명령 | 산출물 |
|---|---|---|
| A. Scenario Specification | `scenarios.py`, `koimplicit scenarios` | 참여자, 의도 정답, 이전 참조 대상, distractor, 조건(target_role, referent_shift, distractor, context_distance, n_turns), 필요한 문맥, 자연성·단서 제약, 변형 선언(manipulated_variables, expected_gold_change, pair_with) |
| B. Dialogue Generation | `generate.py`, `koimplicit generate` | provider(mock/anthropic/openai)로 초안 생성. gold는 시나리오 의도값 복사본이며 `candidate/unreviewed`로만 저장. `generation_log.jsonl`에 프롬프트 버전·payload 해시·원문 응답 기록 |
| C. Controlled Variation | `variations.py`, `koimplicit pairs` | pair별로 달라진 변수·발화 목록, 주장한 조작(`manipulated_variables` 또는 `pair_claims`)으로 설명되지 않는 `unclaimed_differences`, `is_single_variable_pair`, 정답 변경 의도 대 관측 |
| D. Data Validation | `validate.py`, `koimplicit validate` | 스키마, 턴·화자, gold 식별성, 중복, 조건 불균형, pair·시나리오 연결, 평가 입력 gold 누수, 출처·검수 상태. 의미 모호성은 판정하지 않고 `HUMAN_REVIEW` 표시만 한다 |
| E. Human Annotation | `annotation.py`, `koimplicit annotate` | 검수자별 CSV(정답 숨김, 순서 섞음) → 일치도(percent, Cohen's κ) → pair 시트 → 조정. 최초 판정은 `validation_metadata.annotator_votes`에 보존 |
| F. Payload | `payload.py`, `koimplicit payload` | `items.jsonl`(정답 없음)과 `gold.jsonl` 분리. 후보 순서는 seed와 family_id로 고정 |
| G. Benchmark | `benchmark.py`, `koimplicit benchmark` | 독립 요청·캐시·재시도(`runner.py`), 파싱(`normalize.py`), 지표(`metrics.py`), 비용 추정, 표본별 CSV |
| H. Baselines / 통계 | `baselines.py`, `bootstrap.py`, `koimplicit baselines`, `koimplicit metrics` | most_recent_entity, current_speaker, current_addressee, target-only LLM, full-context LLM; scenario 단위 cluster bootstrap |

## 5. Pilot v0 (후보 20개)

| family | 유형 | 표본 | 조작 |
|---|---|---|---|
| S01 회사 옮긴 친구 | controlled, 2인+제3자 2 | base / distractor / shift | 최근성 경쟁 개체 삽입(정답 유지), 질문 대상 전환(정답 변경) |
| S02 발표 준비 | controlled | addressee / speaker / third | 같은 서술어 `고생 많았다`의 역할 삼중 |
| S03 주말 약속 | controlled, 3인 | vocative / novocative | 호격 제거 → 청자 미확정, gold 없음(평가 제외) |
| S04 이모 전화 | controlled | base / distractor | 높임이 두 제3자에 공통인 상태에서 최근성 경쟁 |
| S05 리허설 | controlled | addressee / speaker | 의무 표현 `-아야 돼`의 화자·청자 전환 |
| S06 선배 연락 | controlled | d1 / d5 | 문맥 거리 1 → 5 |
| S07 유학 결정 | controlled | hearsay / speaker / plain | 전문 어미 `-대` 유무, 질문 대상 전환 |
| N01~N03 | naturalistic | 각 1 | 통제 없음(화자 / 3인 청자 / 제3자) |

자동 검증 결과(2026-10-10): 오류 0, 경고 2(anchor 없는 통제 표본 S02-third, S05-speaker), 20개 전부 사람 검수 표시. pair 10개 중 단일 변수 7, compound 3(S02 base~speaker, S02 speaker~third, S05 base~speaker: 역할을 바꾸려면 발화 구조를 바꿔야 했다). 역할 분포: third_party 11, speaker 4, addressee 4, 미확정 1.

작성자: Claude Fable 5.1(Claude Code 세션에서 직접 작성, API 호출 아님). `creation_method=llm_authored`. 작성자 라벨은 **의도값**이며 검수 전까지 gold가 아니다.

## 6. 검수 절차

1. 검수자 2명이 `annotate sheets`로 만든 CSV를 독립적으로 채운다. 항목: 자연스러움(1~5), 참조 대상 ID, 역할, 문맥 충분성, 모호성, 이전 참조 대상(anchor), 메모.
2. `annotate agreement`로 필드별 일치도와 κ를 계산한다. 이 값은 gold 제작 품질이지 인간 상한이 아니다.
3. 독립 판정이 끝난 뒤 `annotate pair-sheet`로 두 버전을 나란히 보고 minimal pair 타당성·단일 변수 여부·정답 변경 의도를 판정한다.
4. `annotate adjudicate`: 전원 일치(정답·unambiguous) → accepted; 전원 모호 → rejected; 불일치 → 조정 파일(`adjudication.csv`: decision accept/reject, final_referent_id, reason)로 수정 또는 제외. 작성자 gold가 바뀌면 `author_gold_overridden`에 기록한다.
5. accepted만 `payload`에 들어간다. 모델 결과를 본 뒤 gold·후보·제외 기준을 바꾸지 않는다. 바꿔야 하면 버전을 올린다.

## 7. 평가 설정

- 조건: `full_mcq`(전체 문맥 + 후보), `target_only_mcq`(목표 발화만 + 후보), `full_qa`(후보 없음, 응답을 entity ID로 매핑). 구조화 출력 강제 여부는 모든 조건에서 같다.
- 프롬프트: `prompts/mcq_v1.json`, `qa_v1.json`. 후보는 ID와 이름만 노출한다. `validate`가 렌더링된 프롬프트에 역할어·gold가 없는지 확인한다.
- 모델 설정: `configs/models.json`(provider, model_id, decoding, 단가, seed 지원 여부). 실행마다 `config.json`에 model_id·prompt 해시·items 해시·날짜·조건을 기록한다.
- 재시도: 네트워크·서버 오류만 같은 payload로 최대 2회. 형식 오류·오답을 보고 재질문하지 않는다.
- 지표: overall accuracy, by referent type / shift / speaker change / distractor / distance / dataset, distractor error rate, context benefit(full − target_only, 같은 항목 paired), pair consistency, role·entity confusion matrix, parse status 비율. CI는 scenario 단위 cluster bootstrap.

## 8. 재현성

- seed 기본값 20261010. 후보 순서(payload), 검수 시트 순서(annotate), 요청 순서(runner)에 쓰인다.
- 데이터셋 버전: 폴더 이름(`pilot_v0`)과 레코드 `version`. 동결 후 변경은 새 버전으로.
- 생성·평가 프롬프트는 `prompts/`에 버전 파일로 두고 실행 기록에 sha256을 남긴다.
- 모델 응답은 payload 해시로 캐시되어 같은 요청을 다시 보내지 않는다.

## 9. 알려진 편향과 위험

- **생성 모델 = 평가 모델 편향**: Pilot 작성자(Claude Fable 5.1)와 평가 후보(Claude 계열)가 같은 계열이다. 결과 보고 시 반드시 명시하고, human-authored 표본(`creation_method=human_authored`)을 추가해 비교하도록 스키마를 준비했다. `by_creation_method` 집계가 그 비교용이다.
- **작성자 라벨 오류**: S01-shift, S04-distractor, S07-plain, N02-01은 작성자도 대안 해석 가능성을 메모했다. 검수에서 확정한다.
- **단서 의존**: N03의 `친정`, N01의 높임 부재, S07의 `-대`처럼 어휘·어미 단서로 풀리는 표본이 있다. `linguistic_cues`로 기록하고 분석에서 분리한다. 단서 사용 자체를 잘못된 추론으로 해석하지 않는다.
- **역할 불균형**: 제3자가 과반이다. 확장 시 화자·청자 표본을 늘린다.
- **compound 변형**: 역할 전환 pair 3개는 단일 변수 조작이 아니다. 단일 cue minimal pair라고 부르지 않는다.
- **3인 대화 청자**: 호격 없는 청자 판정(N02)은 담화 추론에 의존한다. 검수자 불일치가 크면 제외한다.
- **규모**: 20개는 pilot이다. 셀별 표본이 작아 CI가 넓다. 600개 확장은 pilot 검수와 스키마 동결 뒤에 한다.

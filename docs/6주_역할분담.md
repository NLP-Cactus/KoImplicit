### 예비 집계

`koimplicit audit` 명령으로 재현할 수 있다(2026-10-10 확인). 값 옆에 확인 상태를 적었다. **구조 audit의 사람 확인이 끝나기 전까지는 예비 수치**다.

**2025 구어 (주자료)**

| 항목 | 값 | 의미 | 확인 |
|---|---|---|---|
| 문서 수 | 75개 | 2인 일상 대화 63, 1인 독백 12 | audit 일치 |
| 2인 대화 문장 수 | 15,175 | 모든 문장에 `speaker_id` 있음, 화자 목록과 100% 연결 | audit 일치 |
| 화자 | 126명 | 대화 간 중복 0 → 대화 63개를 독립 단위로 볼 수 있음 | audit |
| 인접 문장 같은 화자 비율 | 85% | 문장 ≠ turn. speaker-run 2,326개 | audit |
| 2인 대화의 주어 생략 | 15,512 | 무생물·집합·일반 지시 포함, 필터 전 | audit 일치 |
| 텍스트 선행사 없음 (`#`) | 3,347 | 복원형이 `화자가` 900, `청자가` 504, `누군가가` 1,360, `무언가가` 531 등 | 별도 재계산 일치 |
| 참여자형 복원 (`내가`, `제가`, `네가` 등) | 약 6,500 | `우리가` 613 등 복수형 포함, 필터 전. 대명사 목록 정의에 따라 6,500–6,900 | 정의에 따라 변동 |
| 선행사가 목표 문장보다 뒤에만 있음 | 251 | 앞 문맥만으로 판정 불가 후보 (`future_dependent`) | 재계산 일치 |
| 선행사가 모두 상대 화자 발화에 있음 | 1,058 | speaker 전환 분석 후보 | 재계산 일치 |
| 상대 화자의 나/너 계열 대명사에 연결된 주어 | 347 | 아래 6번. 사람이 다시 판정할 대상 | audit |
| 대화 관계 (2인 대화 63개) | 친구 24, 부부 13, 기타 8, 연인 7 등 | 초안의 "기타 20"은 독백 12개가 섞인 값 | 수정 |

여기서 확인한 것:

1. **화자 정보는 문장 단위로 있다.** 설계안이 우려한 speaker 연결은 가능해 보인다.
2. **원래 발화(turn) 경계 정보는 없다.** 문장 ID가 `문서.1.1.N` 형태라 연속한 같은 화자 문장을 묶는 **speaker-run proxy**를 써야 할 가능성이 크다. 일부 문장 ID(662개)는 `문서.1.1.1.N`처럼 한 단계가 더 있어 의미를 확인해야 한다.
3. **`화자`/`청자` 복원은 2025 지침에서 새로 추가됐다** (2025 보고서 표 35). 범위(앞 15문장·뒤 2문장) 안에 동일지시 성분이 없을 때 쓴다. 설계안의 deictic 사례에 해당하고 `speaker_id`로 인물에 매핑할 수 있다. `누군가가`/`무언가가`는 범위 안에 선행어가 없을 때의 비지시적 대명사이므로 제외 대상이다.
4. **설명서에는 `#`의 정의가 없지만 사업 보고서에 지침이 있다.** 2025 보고서 [붙임5] "무형 대용어 복원 말뭉치 구축 지침"(PDF p.325 부근).
5. 필터 전 후보가 매우 많으므로 **목표 120개는 수량 문제가 아니라 판정 품질 문제**다.
6. **원 주석의 복원 형태는 목표 발화자 기준이 아니다.** 2025 지침 2.2.3.2는 "동일지시적 성분의 인칭을 그대로 복원한다"고 정한다. 그래서 화자가 바뀌어도 `내가`↔`네가`로 바꾼 연결이 0건이다. 상대 화자의 대명사에 연결된 347건을 표본으로 읽은 결과 두 유형이 있었다.
   - 선행어는 맞는 사람이고 복원 형태만 상대 화자 기준인 경우: 지침대로다.
   - 선행어가 다른 사람을 가리키는 경우: 오류다. 표본 11건 중 약 9건이었다(비율 확정치 아님).
   - 따라서 **인물 gold는 복원 형태가 아니라 선행어를 말한 화자 기준으로 만들고, 347건은 자동 변환하지 않는다.** 2024 보고서가 원천 말뭉치의 대화자 ID 오류를 언급하므로 발화자 라벨 오류 가능성도 남겨 둔다.

**2024 구어**

- 문서 614개, 2인 대화 외에 3–4인 대화 포함.
- **문장에 `speaker_id`가 없고** 문서 메타에 화자 정보도 없다. ZA 주석이 문서 단위에 있고 선행사에 `type`이 붙는 등 2025와 구조가 다르다. `화자`/`청자` 복원 라벨도 없다.
- 설계안 4.1절대로 MVP에서 제외하는 것이 맞다. 쓰려면 원본인 일상 대화 말뭉치 2022가 필요하다.

## 5. 4주차 (11/02–11/08): 통제 실험 A/B와 계획 동결

### 통제 쌍 작성과 검증

작성자는 자기 쌍을 검증하지 않는다. 검증자 2명은 두 버전을 나눠서 받아 따로 판정한다 (설계안 9–10절).

| 작성자 | 실험 A | 실험 B | 검증자 |
|---|---|---|---|
| 정택준 | 4쌍 | 4쌍 | 서진정, 임동건 |
| 서진정 | 4쌍 | 4쌍 | 정택준, 임동건 |
| 임동건 | 4쌍 | 4쌍 | 정택준, 서진정 |

- 실험마다 6개 이상의 서로 다른 상황·서술어 구조. 이름만 바꾼 쌍은 같은 family로 묶는다.
- 개발 자연 자료에서 현상을 찾을 수 있다. **held-out 자료는 seed로 쓰지 않는다.** 원문 기반 쌍과 독립 창작 쌍을 구별해 기록한다.
- A: 목표 발화·후보·발화자 표시는 그대로 두고 앞선 관계만 바꿔 정답이 실제로 달라져야 한다.
- B: 새 인물 없이 비정답 인물 언급 위치만 옮기고 정답이 유지되어야 한다. 정답 인물 언급 거리를 맞추지 못하면 compound order intervention으로 따로 표시.
- `초기설계_검토.md`에서 지적한 `도` 같은 조사 단서처럼 정답을 의도치 않게 바꾸는 표현을 검증 때 확인한다.
- 합의하지 못한 쌍은 수정하거나 제외한다. 모델 결과를 보고 기준을 바꾸지 않는다.

**서진정**: 검증 배정·회수·합의 판정, 유효 pair 목록.
**정택준**: 통제 쌍을 평가 입력 형식으로 변환, pair/family ID 관리.
**임동건**: 개발 자료로 prompt 최종 확인, cluster bootstrap 코드 (자연: 대화 단위, 통제: family 단위).

- [ ] prompt 버전, 출력 형식, decoding 설정
- [ ] 지표·분석 계획, 제외 기준
- [ ] held-out QA subset 약 24개 선택 (모델 결과를 보기 전에)
- [ ] 동결본을 커밋하고 이후 변경은 새 버전으로 기록

## 9. 협업 규칙

- **정기 회의**: 주 2회 (예: 화·금). 화요일 진행 점검, 금요일 주차 산출물 확인.
- **저장소**: 학기 중에는 private로 유지한다 (`초기설계_검토.md` 7절, 벤치마크 오염 방지). **2026-10-10 확인 시 PUBLIC이므로 소유자가 전환해야 한다.**
- **권한**: 팀원 전원이 branch를 push할 수 있도록 소유자가 write 권한을 준다.
- **Git**: 각자 작업 branch를 만들고 PR로 합친다. PR은 다른 한 명이 확인한다.
- **Git 제외 자료**: `data/`, `annotations/`, `results/`의 실제 자료는 커밋하지 않는다. 공유는 약정 범위 안의 방법을 쓴다.
- **비밀정보**: API 키는 `.env`에만 둔다.
- **기록**: 계획, 구현 상태, 실제 결과를 구별한다. 하지 않은 검증을 완료라고 쓰지 않는다.

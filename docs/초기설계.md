# 1. 프로젝트 목표

### 프로젝트명 가칭: `K-ImplicitTrack`

**연구 주제**

> 한국어 다중턴 대화에서 화자·청자·담화 대상 전환에 따른 LLM의 생략 논항 추적 능력 분석

**핵심 연구 질문**

> LLM은 한국어의 생략된 논항을 해결할 때 실제로 discourse participant state를 추적하는가, 아니면 최근 등장 entity나 종결 표현 같은 표면적 cue에 의존하는가?

따라서 프로젝트는 크게

**Benchmark 구축 → LLM 평가 → Controlled Intervention → Failure Analysis**

4단계로 구성하면 된다.

# 3. 데이터 Schema부터 확정

처음 구현해야 하는 게 이거야.

예를 들면 JSONL 한 줄을:

```json
{
  "id": "pilot_shift_001",
  "dialogue": [
    {
      "speaker": "A",
      "text": "민수가 내일 학교 온대?"
    },
    {
      "speaker": "B",
      "text": "응. [Ø] 온다고 했어."
    }
  ],

  "target_turn": 1,
  "target_argument": "subject",

  "gold": {
    "referent": "민수",
    "referent_type": "third_party"
  },

  "condition": {
    "shift": false,
    "distance": 1,
    "distractor": false
  },

  "template_id": "T001",
  "pair_id": "P001",

  "source": "controlled",
  "ambiguous": false
}
```

여기서 `pair_id`가 꽤 중요해.

나중에 minimal pair:

```text
original
cue_removed
distractor_added
```

가 모두 같은 원본에서 파생됐다는 걸 추적할 수 있다.

# 4. Referent taxonomy

처음부터 taxonomy를 문서로 박아두자.

### Referent Type

```text
SPEAKER
ADDRESSEE
THIRD_PARTY
AMBIGUOUS
```

예를 들어:

### Speaker

```text
A: 너 내일 갈 거야?
B: 응. [Ø] 갈 거야.
```

Gold:

```text
SPEAKER(B)
```

### Addressee

조건에 따라 발화 행위/명령/질문 구조에서 상대방이 생략된 논항이 되는 사례.

### Third Party

```text
A: 민수 내일 온대?
B: 응. [Ø] 온다고 했어.
```

Gold:

```text
THIRD_PARTY(민수)
```

### Ambiguous

```text
A: 민수랑 지훈이 만났어?
B: 응. [Ø] 밥도 먹었대.
```

문맥만으로 누가 특정 행동의 주체인지 유일하게 결정되지 않는 식의 사례.

단, `AMBIGUOUS`는 **메인 benchmark가 아니라 별도 subset**으로 두는 걸 권장해.

# 5. 핵심 독립변수

처음부터 너무 많이 넣지 말자.

## Main Experiment

딱 네 개.

| Variable | Values |
|---|---|
| Referent | Speaker / Addressee / Third-party |
| Shift | No / Yes |
| Distance | 1 / 3 / 5 turns |
| Distractor | No / Yes |

Omission Type은 일단 **Subject만**.

이게 중요해.

주어+목적어를 처음부터 같이 하면 한국어의 case/verb semantics까지 복잡하게 얽힌다.

### Phase 2에서

`Subject → Object`

를 확장하면 된다.

# 6. Shift를 정확히 정의

이걸 애매하게 하면 나중에 데이터가 망가져.

### No Shift

최근 discourse focus와 target referent가 동일.

```text
A: 민수 어제 학교 갔대?
B: 응. 수업도 들었대.
A: [Ø] 과제도 냈대?
```

계속 민수.

### Shift

직전 discourse focus와 target referent가 다름.

```text
A: 민수 어제 학교 갔대?
B: 응. 지훈이는 집에 있었대.
A: 근데 [Ø] 과제는 냈대?
```

target이 민수라는 게 **문맥적으로 명확하도록 추가적인 단서가 반드시 있어야 한다.**

단순히 연구자가 "정답 민수"라고 정하면 안 됨.

이게 annotation에서 가장 주의해야 할 부분.

---

# 7. Distractor 정의

그냥 아무 문장 넣는 게 아니다.

우리가 테스트하고 싶은 건 **recent-entity heuristic**이니까:

> 정답이 아닌 entity를 target 직전에 등장시킨다.

Control:

```text
민수가 프로젝트를 맡았다.
...
[Ø] 발표도 준비했다.
```

Distractor:

```text
민수가 프로젝트를 맡았다.
...
지훈이는 자료 조사를 도왔다.
[Ø] 발표도 준비했다.
```

Gold는 민수로 유지.

그러면 모델이 지훈을 선택하는지 볼 수 있다.

---

# 8. Dataset Generator

완전히 LLM으로 생성하지 말고 **구조는 deterministic하게 생성**하는 게 좋아.

```text
Scenario
   ↓
Entity assignment
   ↓
Dialogue template
   ↓
Condition manipulation
   ↓
Surface realization
   ↓
Validation
```

예를 들어 template:

```python
{
    "context": "{target}가 프로젝트를 맡았다고 했어.",
    "distractor": "{distractor}는 자료 조사를 도와준대.",
    "target": "[Ø] 발표도 준비하고 있대."
}
```

여기에:

```text
민수
지훈
수현
```

등을 랜덤 배정.

LLM은 나중에 **문장을 자연스럽게 paraphrase하는 용도** 정도로만 사용하고, gold label 생성에는 관여시키지 않는 게 안전하다.

Distance는 Pilot에서는 우선 `1 / 3` 정도만 일부 포함.

Pilot의 목적은 논문 결과가 아니라:

> **현재 모델에게 이 문제가 실제로 어려운가?**

확인하는 것.

# 10. Pilot 모델

처음부터 7개 돌릴 필요 없어.

성격 다른 **3개 모델**이면 된다.

예:

```yaml
models:

  model_a:
    family: qwen

  model_b:
    family: gemma

  model_c:
    family: korean_oriented
```

실제 모델 버전은 실험 시작 직전에 고정.

모든 결과에는 반드시:

```text
model
model_version
date
temperature
prompt_version
dataset_version
```

을 기록해.

LLM 논문은 몇 달만 지나도 모델이 바뀌니까 재현성 때문에 중요하다.

---

# 11. Prompt

처음엔 가장 단순한 prompt 하나만.

```text
다음 대화에서 [Ø]에 생략된 주체를 판단하세요.

{dialogue}

선택지:
A. 화자 A
B. 화자 B
C. 민수
D. 지훈
E. 문맥만으로 판단할 수 없음

정답의 알파벳 하나만 출력하세요.
```

그리고 choice ordering은 **randomize**하는 게 좋다.

항상:

```text
A speaker
B addressee
C third-party
```

면 position bias가 생길 수 있으니까.

Gold에는 entity ID를 저장하고 runtime에서 choice mapping을 생성한다.

# 12. Inference 결과 Schema

Raw output은 절대 버리지 않는다.

```json
{
  "item_id": "pilot_001",
  "model": "...",
  "prompt_version": "v1",
  "gold": "entity_01",

  "choices": {
    "A": "entity_02",
    "B": "entity_01",
    "C": "unknown"
  },

  "raw_response": "B",
  "parsed_answer": "entity_01",
  "correct": true,

  "latency_ms": 832
}
```

나중에 parsing 문제가 생겨도 재실험할 필요가 없다.

# 13. Pilot GO / NO-GO 기준

이걸 **실험 전에 정해놓는 것**을 추천해.

### Case A — 성능 차이가 보임

예:

```text
Control       91%
Shift         78%
Distractor    69%
```

**GO.**

본 benchmark 제작.

### Case B — 전부 95~100%

주제 폐기 X.

난도 증가:

```text
2-party
↓
3-party

single shift
↓
multiple shifts

1 turn
↓
3/5 turns

single distractor
↓
multiple plausible distractors
```

그리고 다시 Pilot.

### Case C — 전부 너무 낮음

예:

`30~40%`

문항 자체가 모호하거나 unnatural할 가능성이 큼.

human validation부터 다시 한다.

---

# 14. Human Baseline

이건 초기 설계에 꼭 넣자.

Pilot 중 30~50개 정도를 사람에게 풀게 한다.

목표는:

> 모델보다 사람이 잘하는지

보다

> **우리가 만든 문제에 실제로 유일한 정답이 있는지**

확인하는 것.

사람 agreement가 낮으면 해당 문항은 benchmark에서 제외.

본 데이터에서는 2명 이상 독립 annotation + Cohen's κ.

---

# 15. Cue Intervention은 Pilot 이후

Pilot이 성공하면 가장 재미있는 Phase 2.

동일한 문항에서:

```text
Original

Speaker Label Removed

Recent Distractor Added

Ending Normalized

Honorific Cue Removed
```

등을 만든다.

예:

**Original**

> B: 응, 갈게.

**Ending intervention**

> B: 응, 간대.

처럼 단순 문자열 치환하면 의미가 달라질 수 있으므로, intervention마다 **gold referent가 그대로 유지되는지 human validation**해야 한다.

이 부분이 논문에서 가장 까다롭지만 가장 가치가 높을 거야.

---

# 16. Natural Dataset은 마지막

국립국어원 무형 대용어 복원 말뭉치를 처음부터 전처리하려고 하지 말자.

순서는:

```text
Controlled Pilot
        ↓
failure 발견
        ↓
Controlled Benchmark
        ↓
failure pattern 확정
        ↓
Natural Corpus
        ↓
실제 데이터에서도 동일한가?
```

그래야 natural corpus 분석의 목적이 생긴다.

그냥 국립국어원 데이터를 모델에 넣고 accuracy 계산하면 기존 ZAR evaluation과 별 차이가 없어져.

# 18. 팀원 역할

3인 기준이면 이렇게 나누는 게 깔끔해.

**A — Dataset / Linguistics**

논문 조사, taxonomy, template, annotation guideline, natural corpus.

**B — Experiment / Engineering**

inference harness, model adapters, experiment config, reproducibility.

**C — Evaluation / Analysis**

metrics, statistical analysis, visualization, error taxonomy.

다만 dataset 1명에게 몰아주면 힘들어서 **Pilot 72개는 셋이 같이 검수**하는 게 좋아.

## README 첫 문장도 이렇게 잡으면 돼

> **K-ImplicitTrack investigates whether large language models genuinely track implicit discourse participants in Korean multi-turn dialogue or rely on shallow surface cues such as recency and speaker-related linguistic markers.**

그리고 가장 먼저 만들 파일은 코드가 아니라 **`docs/dataset_spec.md`**야. 여기에 `referent`, `shift`, `distractor`, `ambiguous`의 정의와 positive/negative example을 먼저 박아놓고 세 명이 합의한 다음 generator를 구현해야 해.

이 설계대로라면 **1차 목표는 "이번 주에 72개 Pilot을 만들어 실제 모델을 돌려보는 것"**으로 잡으면 된다. Pilot 결과가 나오면 그때부터 데이터 규모와 intervention 설계를 **결과 기반으로** 확정하는 게 가장 안전해.

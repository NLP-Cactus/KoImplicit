# Correct-Detect 논문 정리

> **설계 이력 문서(2026-10-10 이후 실행 기준 아님).** 이 프로젝트는 국립국어원 말뭉치를 사용하지 않기로 했고 데이터 전략을 독립 창작 데이터셋으로 바꿨다. 이 문서의 말뭉치 사용 전제, 모델 결과에 따른 난도 조정, distractor 선택을 곧바로 이해 실패로 보는 해석은 현행 규칙과 다르다. 현행 절차는 [docs/데이터셋_구축방법.md](데이터셋_구축방법.md)와 [AGENTS.md](../AGENTS.md)를 따른다. 연구 기록으로 보존한다.

- **제목:** Correct-Detect: Balancing Performance and Ambiguity Through the Lens of Coreference Resolution in LLMs
- **저자:** Amber Shore, Russell Scheinberg, Ameeta Agrawal (Portland State Univ.), So Young Lee (Miami Univ.)
- **게재:** EMNLP 2025 Main, pp. 30044–30058, DOI 10.18653/v1/2025.emnlp-main.1527 (arXiv:2509.14456)

## 1. 한 줄 요약

LLM은 프롬프트에 따라 **대명사 지시 해소(Correct)**도 잘하고 **모호성 탐지(Detect)**도 잘할 수 있지만, **두 능력을 동시에 높게 유지하지는 못한다.** 저자들은 이를 CORRECT-DETECT trade-off라고 부른다.

## 2. 연구 질문

| 질문 | 내용 |
|---|---|
| Alignment | 모호/비모호 문장 모두에서 LLM의 선택이 사람의 선호와 얼마나 일치하는가 |
| "Correct" accuracy | 사람이 한 해석을 강하게 선호하는 비모호 문장에서 얼마나 정확한가 |
| "Detect" ambiguity | 사람에게도 진짜 모호한 문장을 맥락이 충분한 문장과 구분하는가 |
| Balance | 둘을 동시에 잘할 수 있는가 |

저자들이 주장하는 기여: 모호한 경우와 비모호한 경우 모두에서 coreference 판단을 **사람 판단과 직접 비교**한 첫 연구.

## 3. 데이터셋

### AmbiCoref (Yuan et al., Findings of EACL 2023) — 메인

- 영어, **템플릿으로 생성한 minimal pair** 문장. 각 문장은 두 사람이 나오는 첫 절 + 둘 중 하나를 가리키는 대명사(he/she)가 있는 둘째 절로 구성된다.
- 각 문장에 지시 대상을 묻는 질문이 붙는다. (예: "Who saw that the rain had stopped?")
- 사람 응답(5점 척도) annotation이 포함돼 있어 LLM과 직접 비교할 수 있다.
- 총 **1,930문장** (비모호 962 / 모호 968), 동사의 의미 성질에 따라 4개 범주:

| 범주 | 의미 | 비모호 | 모호 | 계 |
|---|---|---|---|---|
| ECO (Experiencer Constraint for Objects) | 동사가 목적어를 경험자로 제약 | 331 | 332 | 663 |
| ECS (Experiencer Constraint for Subjects) | 동사가 주어를 경험자로 제약 | 131 | 129 | 260 |
| IC (Implicit Causality) | 동사가 함의하는 인과가 지시 대상을 제약 | 260 | 261 | 521 |
| TOP (Transfer of Possession) | 소유 이전(출발점→도착점) 논리로 결정 | 240 | 246 | 486 |

- 주의: "비모호" 문장도 한쪽으로 **편향**돼 있을 뿐 절대적으로 비모호하지는 않다고 저자들이 직접 밝힌다(각주 1). 그래서 정답 = "의미적으로 편향된 해석과의 일치"로 정의한다.
- 성별: 여성 대명사·이름 문장 51%, 남성 49%. 한 문장 안에서 성별을 섞지 않는다.

### AmbiEnt (Liu et al., EMNLP 2023) — 일반화 확인용

- 함의(entailment) 데이터셋. 모호성 유형이 annotation된 부분집합 중 coreference 관련 **62쌍(124문항)**만 사용.

## 4. 모델·실험 설정

- **GPT-4o** (gpt-4o-2024-08-06), **Llama 3.1 70B Instruct**
- 모델당 1,930문장 × **3회 실행** = 5,790 응답
- 추가: OpenAI **o3** (Correct-Detect 실험 일부만)
- 예비 실험에서 **선택지 순서 편향(order bias)**이 보여서 후보 목록을 제시하지 않았다 (Pezeshkpour & Hruschka, 2024 참조).

## 5. 실험과 결과

### 실험 1. REFLECT — 사람 패턴을 따라가는가

사람 annotator가 받은 지시문을 그대로 주고 5개 중 하나를 고르게 했다.
`Definitely A / Probably A / Mostly ambiguous / Probably B / Definitely B` → 스키마 `[A, A?, ?, B?, B]`

**결과**
- 사람: 비모호 문장에서는 U자형(확신 응답이 많음), 모호 문장에서는 역U자형(`?`가 늘어남)으로 분명히 바뀐다.
- Llama 3.1: 비모호 문장에서도 `?`를 과도하게 고르고, 모호 문장으로 가도 분포가 거의 그대로다.
- GPT-4o: 비모호 문장에서는 사람과 꽤 비슷하지만, 모호 문장에서 `?`가 조금 늘어날 뿐이다.
- 범주별 χ² 검정에서 두 모델 모두 모든 범주에서 사람과 분포가 유의하게 다르다 (p 매우 작음, Table 13).

**응답 일관성 (같은 문장 3회 응답이 같은 비율, Table 3)**

| | 비모호 평균 | 모호 평균 | Δ |
|---|---|---|---|
| Human | 21.61 | 9.38 | **12.23** |
| Llama 3.1 | 25.66 | 23.59 | 2.07 |
| GPT-4o | 43.46 | 40.40 | 3.06 |

→ 사람은 모호성에 반응해 일관성이 크게 떨어지는데, 모델의 변화폭은 사람의 약 1/4 수준이다.

**비모호 문장 정확도 (Table 4)**

| | strict (5지선다) | near (A/A?, ?, B?/B 3지선다) |
|---|---|---|
| Human | 50.94 | 76.77 |
| Llama 3.1 | 38.39 | 43.07 |
| GPT-4o | 43.38 | 79.52 |

**부가 발견**
- **묻지 않은 설명을 붙이는 비율 (Table 5):** Llama는 67.53%, GPT-4o는 12.75%. GPT-4o는 설명을 붙인 응답의 정확도(29.50%)가 붙이지 않은 응답(45.10%)보다 낮아서, 설명이 "어려운 문항"의 신호가 된다. Llama는 설명 유무와 정확도 사이에 유의한 관계가 없다.
- **성별 편향 (Table 6):** 사람은 여 49.14 / 남 52.86으로 비슷하다. 모델은 Llama 29.34 / 47.90, GPT-4o 34.89 / 52.31로, 여성 대명사·이름 문장에서 크게 떨어진다.

### 실험 2. CORRECT — 사람 흉내를 빼면 얼마나 맞히나 (비모호 문장만, Table 8)

| 프롬프트 | Llama 3.1 | GPT-4o |
|---|---|---|
| REFLECT (near) | 43.07 | 79.52 |
| **BASIC** (문장+질문만) | **90.33** | 87.70 |
| CoT | 86.38 | **89.99** |
| WSC ("Who is <pronoun> referring to?") | 39.50 | 39.43 |
| WSC-1sh (1-shot) | 69.82 | 45.43 |

- **지시문이 많을수록 오히려 성능이 떨어진다.** Llama는 REFLECT 43% → BASIC 90%.
- WSC식 질문에서는 Llama가 문제를 유명 인물을 묻는 개체 판별로 오해하는 경우가 많았다.
- 효율까지 보면 BASIC이 최선이다 (평균 응답 14단어, CoT는 GPT-4o 135단어).

### 실험 3. CORRECT-DETECT — 둘 다 잘할 수 있나 (Table 10, Figure 3)

BASIC을 바탕으로 모호성 가능성을 강조하는 프롬프트 5종을 만들었다: Ambi-Ask / Ambi-Stop / Ambi-Wait / Ambi-Doubt / Ambi-CoT.
- **Correct-Unamb** = 비모호 문장 정확도
- **Detect-Ambig** = 모호 문장에서 `?`, `A?`, `B?`를 고른 비율

| 모델 | 프롬프트 | Detect | Correct |
|---|---|---|---|
| Human | REFLECT (near) | 78.47 | 76.77 |
| Llama 3.1 | BASIC | 3.72 | 90.33 |
| Llama 3.1 | Ambi-Stop | 44.35 | 61.47 |
| Llama 3.1 | Ambi-CoT | 75.17 | 42.90 |
| GPT-4o | BASIC | 22.86 | 87.70 |
| GPT-4o | Ambi-Ask | 83.37 | 41.93 |
| GPT-4o | Ambi-Wait | **99.55** | **5.23** |
| o3 | Ambi-Ask | 73.17 | 41.55 |
| o3 | Ambi-Stop | 84.47 | 36.04 |

- 모든 설정이 Pareto front 위에 놓이고, **둘 다 높은 우상단에는 어떤 모델도 없다.** 사람만 그 근처에 있다.
- 같은 프롬프트라도 모델마다 효과가 정반대다. Ambi-Ask는 GPT-4o에서는 가장 균형 잡힌 결과를 냈지만, Llama에서는 Detect가 최저(5.54%)였다.
- 추론 모델(o3)도 같은 trade-off를 보인다. 추론을 하면 탐지는 오르고 정확도는 내려간다.

### 실험 4. AmbiEnt — 다른 과제에서도 그런가 (Table 12)

| 모델 | 프롬프트 | Correct | Detect |
|---|---|---|---|
| Llama 3.1 | Ambi-Ask / Ambi-Stop | 67.74 / 70.97 | 0 / 1.61 |
| GPT-4o | Ambi-Ask / Ambi-Stop | 74.19 / 69.35 | 0 / 20.97 |

- 함의 과제에서는 애초에 모호성을 거의 인정하지 않는다 (Detect 0~21%). 그래서 trade-off 자체를 드러내기 어려웠다고 저자들이 직접 인정한다.

### Discussion

- Kalai et al.(2025) "Why language models hallucinate"와 연결한다. 학습·평가가 "모른다"보다 **자신 있게 찍는 것**에 보상을 주기 때문에 모호해도 답을 고른다는 가설이다.
- 다만 언어적 모호성 탐지는 사실성 환각보다 해결 가능성이 높다고 본다.

## 6. 한계점

### 6-1. 저자가 명시한 한계 (Limitations 절)

1. **모델 수:** 두 모델(+o3 일부)뿐이다. 모델을 더 넣으면 결론이 강해진다.
2. **영어만:** 언어마다 모호성의 성질이 다르므로 다른 언어는 따로 연구해야 한다.
3. **문장 유형 제한:** 등장인물 수(mention 수)와 **맥락 길이가 의도적으로 제한**돼 있다. 저자들은 둘 다 향후 과제로 남긴다.
4. (본문 7절) AmbiCoref처럼 모호/비모호 쌍을 함께 가진 데이터셋이 드물어서, trade-off가 **다른 과제로 일반화되는지 불분명하다.**

### 6-2. 우리가 읽으면서 본 추가 한계 (논문에 명시되지 않음, 우리 해석)

1. **정답 자체가 약하다.** 비모호 문장에서 사람의 strict 정확도가 50.94%다. "비모호"가 실제로는 편향일 뿐이라서 Correct 수치의 상한이 애매하다.
2. **문장 하나 단위·3인칭만 다룬다.** 두 3인칭 인물 중 하나를 고르는 구조라서 대화, 화자/청자 같은 직시(deixis), 턴 사이 추적은 다루지 않는다.
3. **명시적 대명사(he/she)만 다룬다.** 영어라 논항 생략(null argument)이 없다.
4. **왜 그렇게 답하는지는 밝히지 않는다.** 프롬프트를 바꿔 결과를 비교할 뿐, 모델이 어떤 단서(통사 위치, 최근성 등)에 기대는지 cue를 조작해 검증하지는 않는다. 부록 A.3에서 "주어 위치 편향일 수 있다"고 추측하는 정도다.
5. **프롬프트 민감도가 매우 크다.** 같은 모델이 39%에서 90%까지 움직인다. 결론이 특정 프롬프트 집합에 의존할 수 있다.
6. **온도 등 decoding 설정이 본문에 명시되지 않았다.** 3회 실행 일관성을 지표로 쓰면서 샘플링 조건이 불분명하다.
7. **AmbiEnt 검증 규모가 작다.** 62쌍뿐이라 일반화 근거로는 약하다.

## 7. 우리 아이디어와의 비교

| 축 | Correct-Detect | 우리 연구 |
|---|---|---|
| 언어 | 영어 | 한국어 |
| 지시 형태 | 명시적 대명사 (he/she) | **생략된 논항 (null argument / zero anaphora)** |
| 맥락 단위 | 단일 문장 (2개 절) | **다중턴 대화** (1/3/5턴 거리) |
| 지시 후보 | 3인칭 인물 2명 | **Speaker / Addressee / Third-party** (화자·청자 직시 포함) |
| 핵심 변수 | 동사 의미 범주 (ECO/ECS/IC/TOP), 모호/비모호 | **participant shift**, 거리, distractor |
| 메인 질문 | 정확도 vs 모호성 탐지 trade-off, 사람과의 정렬 | 담화 참여자 상태를 추적하는가 vs shallow heuristic(최근성 등)에 기대는가 |
| 진단 방식 | 프롬프트 변형 | **minimal pair + cue ablation** (한 번에 단서 하나만 제거) |
| 사람 데이터 | 기존 데이터셋의 사람 응답 재사용 | 팀원 2인 annotation + Cohen's κ |
| 모호성 | **메인 주제** | supplementary |

### 차별점 정리 (보고서 문장으로 쓸 수 있는 형태)

- Correct-Detect의 Limitations가 직접 남긴 향후 과제 세 가지(**영어 외 언어, 더 긴 맥락, 더 많은 mention**)를 우리 설계가 모두 겨냥한다. 한국어, 다중턴, 3인 이상 + distractor가 그것이다. "기존 연구가 남긴 공백을 메운다"는 근거로 가장 강하게 쓸 수 있다.
- 영어 대명사 해소와 달리 한국어 생략 논항은 **표면에 해소할 형태가 없다.** 그래서 대명사의 성·수 정보 같은 단서를 쓸 수 없고, 담화 상태 추적이 필요하다.
- Correct-Detect는 "무엇이 trade-off되는가"를 보였지만 "모델이 어떤 단서로 푸는가"는 보이지 않았다. 우리의 cue ablation(RQ3)이 이 부분을 채운다.

### 주장하면 안 되는 것

- 모호성 탐지와 정확도의 trade-off 자체를 새 발견처럼 쓰면 안 된다. Correct-Detect가 이미 보였다.
- LLM과 사람의 지시 해소 비교가 최초라고 쓰면 안 된다.

## 8. 우리 설계에 바로 반영할 점

이 논문의 결과가 우리 실험 설계에 직접 걸리는 부분이다. 반영 여부는 팀 논의로 정한다.

1. **객관식 선택지 순서 편향.** 이 논문은 order bias 때문에 후보 목록 제시를 아예 포기했다. 우리는 객관식이 필수이므로 **선택지 순서 무작위화 + 정답 위치 균형**을 반드시 넣고, 가능하면 순서를 바꾼 버전 간 일관성도 보고한다.
2. **"D. 판단할 수 없음" 선택지가 trade-off를 끌고 들어온다.** 선택지에 기권 옵션이 있으면 모델이 그걸 고르는 경향에 따라 정확도가 출렁인다. 이건 이 논문이 보인 바로 그 현상이다. 그러면 shift·distance 효과와 기권 성향이 섞인다. 대안은 둘이다.
   - (a) 메인 실험은 기권 옵션 없이 강제 선택으로 하고, Ambiguous 실험은 따로 둔다.
   - (b) 기권 응답을 별도 범주로 집계해 "기권률"을 지표로 분리 보고한다.
3. **프롬프트 민감도.** 프롬프트 하나로 39%와 90%가 갈리므로 **최소 2~3개 프롬프트 템플릿**으로 돌려서, 우리 효과(shift degradation 등)가 프롬프트를 바꿔도 유지되는지 확인해야 한다. 아니면 리뷰에서 "프롬프트 artifact 아니냐"는 질문을 받는다.
4. **지시문을 길게 쓰지 않는다.** 장황한 지시문(REFLECT)이 성능을 크게 떨어뜨렸다. 메인 프롬프트는 BASIC처럼 간결하게 한다.
5. **이름의 성별 통제.** 성별 편향이 크게 나왔다. 한국어 이름(민수·지훈 등)도 성별 인상이 있으므로 성별을 균형 있게 배치하거나 변수로 기록한다.
6. **반복 실행.** temperature 0만 쓰면 일관성 분석을 할 수 없다. 필요하면 일부 조건은 샘플링 반복으로 보조 분석한다.

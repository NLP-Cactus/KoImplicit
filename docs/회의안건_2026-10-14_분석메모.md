# Pilot v1 CLI 결과 분석 메모 (2026-10-14 회의 1번 안건 보충)

대상: `datasets/pilot_v1/results/cli_summary_20261014.md`. 표본별 CSV(`claudecli_per_sample.csv`, `codex_per_sample.csv`), `dialogues.jsonl`, `labels.jsonl`의 검수 투표, `src/koimplicit/providers/`의 CLI 호출 코드를 함께 확인했다. 새 모델 실행은 하지 않았고 기존 결과만 다시 읽었다.

## 요약

- Haiku의 문맥 이득(+0.29, CI 하한 +0.07)이 이번 pilot에서 가장 쓸 만한 신호다. full 오답 4개 중 1개(S04-distractor)는 설계한 최근성 함정에 정확히 걸렸다.
- gpt-6.1-sol은 이 표본에서 판별력이 없다. full 17/17이고, target_only 13/17은 구조적 상한 15/17(3절)에 가깝다.
- 표본이 최근성과 정렬되어 있다. most_recent_entity 기준선이 매핑된 12개 중 10개를 맞힌다.
- Codex 실행이 정답 파일을 읽을 수 있는 환경이었는지 확인할 수 없다(5절). gpt 수치는 성능 결과로 쓰지 않는다.

## 0. 전제

- n=17, 시나리오 cluster 9개(결과표 머리말의 "10개"는 오기. N01은 유일한 표본 N01-01이 제외되어 평가에 없다. 지표 파일의 `n_clusters`는 9). 1문항은 5.9%p다. 하위표 차이 대부분은 1~2문항 차이다.
- 20개 전부 `llm_authored`(claude-fable-5-1)이다. Haiku는 생성 모델과 같은 계열이다. 이번 표본에서 Haiku가 더 낮았으므로 같은 계열이라 유리한 흔적은 보이지 않는다(n이 작아 결론은 아님).
- 구독 CLI, effort/reasoning low로 실행했다. 호출당 입력 토큰은 Haiku 약 7.4k, Codex 약 17.4k이며 대부분 에이전트 시스템 프롬프트다. API 실행 결과와 직접 비교하지 않는다.

## 3. target_only의 구조적 상한

여러 표본이 같은 목표 발화를 공유한다.

- S01-base / distractor / shift: "응, 그렇다고 하더라. 요즘 많이 바쁘대." 정답은 민수, 민수, 서연.
- S07-speaker / plain: "아니, 아직 결정 못 했어." 정답은 도현, 윤아.
- S04-base / distractor: "다음 주에 올라오신대." 정답은 둘 다 이모.

따라서 target_only에서 얻을 수 있는 최대 정확도는 15/17(0.88)이다. 두 모델 모두 S01 세 개에 민수를 답해 S01-shift만 틀렸다.

- gpt target_only 13/17은 상한 근처다. 사람 Local 판정이 discourse_dependent인 11개 중 8개를 목표 발화만으로 맞혔다. 선택지 안에서 '-대'(화자 배제), 높임, '친정' 같은 국소 단서로 후보를 좁힌 것으로 보인다.
- 안건 1번의 "사람의 Local 판정이 모델 행동을 예측함"은 Haiku(discourse_dependent target 4/11 → full 8/11)에는 맞지만 gpt에는 과장이다. "Haiku에서 관찰됨"으로 범위를 좁히기를 제안한다.

## 4. 기준선과 검수 품질

기준선:

- most_recent_entity는 17개 중 10개를 맞혔다. 매핑 실패 5개는 정답이 화자·청자인 문항이다. 매핑된 12개만 보면 10/12(0.83)이고, 제3자 문항에서는 9/11로 Haiku full(8/11)보다 높다.
- 최근성과 정답이 엇갈리는 문항(distractor 있음)은 2개뿐이다.

검수 표에서 보이는 문항:

- S07-plain: 자연스러움 2(임동건) / 5(정택준). 정택준 Local 판정이 "도현, 명확"으로 Haiku 선택과 같다. 이 오답은 모델 오류보다 문항 문제에 가깝다.
- S01-shift: 정택준 Full 판정이 "ambiguous, 문맥 불충분"인데 accepted 상태다. 두 모델 모두 target_only에서 틀렸다.
- S02-addressee: 자연스러움 2 / 5.

제안: 검수자 한 명이라도 Full에서 ambiguous로 판정하거나 자연스러움 차이가 3 이상이면 조정 대상에 넣는다. 다만 모델 결과를 본 뒤 기존 pilot의 gold·제외 기준을 바꾸지 않는다(AGENTS.md 4절). 위 문항은 기록으로 남기고, 기준 변경은 다음 배치부터 적용한다.

## 5. Codex 실행 환경

- `codex_cli` adapter는 `--sandbox read-only`로 실행하며 `run_cli`에 `cwd`를 넘기지 않는다. 따라서 실행자의 현재 디렉터리(보통 저장소 루트)에서 돈다. read-only 샌드박스는 파일 읽기를 허용하므로 `labels.jsonl`을 읽을 수 있었다. 저장소의 `AGENTS.md`도 자동으로 컨텍스트에 들어갔을 수 있다. "파일을 읽지 않는다"는 system 문구로만 막고 있다.
- `parse_codex_events`가 명령 실행 이벤트를 버리고 원본 응답 로그도 저장소에 없다. 그래서 실제로 파일을 읽었는지 확인할 수 없다. 출력 토큰이 호출당 평균 약 20개라 가능성은 낮아 보이지만 근거로는 부족하다.
- `claude_cli`는 `--tools ""`로 도구를 모두 끄므로 해당하지 않는다.
- 조치 제안: 빈 임시 디렉터리를 `cwd`로 지정하고, `command_execution` 등 도구 이벤트가 있으면 기록하거나 실패로 처리한 뒤 재실행한다.

## 6. 하위표(5~9번)의 해석 한계

- speaker_changed=False n=1, distractor 있음 n=2, 거리 0·5 n≤2로 대부분의 셀이 해석 불가다.
- Haiku referent_changed(False 0.67 < True 1.00)는 가설과 반대 방향이지만 True가 n=3이다.
- 거리 1에서 Haiku target_only 0/6은 거리 효과가 아니다. 직전 질문이 답을 정하는 짧은 문항이 그 칸에 몰린 결과다.

## 7. 회의 반영 제안

1. 발표: Haiku 문맥 이득은 "예비, 개발 점검용"으로 제시한다. gpt는 "천장, 판별력 없음"으로만 언급한다.
2. 다음 배치(안건 2번)의 근거:
   - 최근성과 정답이 어긋나는 문항을 늘린다.
   - 국소 단서('-대', 높임, 어휘)를 통제한 문항을 넣는다.
   - 화자·청자 정답 문항을 늘린다. Haiku의 화자 기본값 검증에도 쓴다.
   - 같은 목표 발화를 공유하는 변형은 target_only 상한을 낮추므로 분석 시 별도 표시한다.
3. 검수: 4절의 조정 기준을 다음 배치부터 적용한다.
4. 평가 코드: Codex `cwd` 분리와 도구 이벤트 기록을 고친 뒤 재실행한다. API 평가에도 같은 원칙(실행 환경에서 정답 파일 접근 불가)을 적용한다.
